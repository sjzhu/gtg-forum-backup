As an aside, I started working on a website that would keep track of a game exactly like this.  It would essentially keep a virtual table for a game, showing which cards were out for each player, keeping track of target hp, etc.  I dropped the project though, for two main reasons:  for one, I was never sure exactly what problem I was trying to solve.  Should the site keep track of each deck so you hit a "draw" button and it tells you what card you've drawn, or should it only wait to be told by the player what card has been played, leaving it to the players to keep track of their own decks and hand.  I had been leaning towards the former, and actually had it working where you could shuffle a deck or look through a deck to pick a card, or shuffle the trash into the deck.  But since I wasn't even sure if that was the functionality it should have, I stopped.

Secondly, the sweet spot I really wanted to hit wasn't possible -- I wanted a group of people to all be able to share the same virtual tabletop.  But since I don't want to use backend storage to keep track of the game's state (I prefer tracking that in the page's URL for various reasons), everyone would have to be accessing the same URL, which meant IMing or email around a new URL whenever any little thing in the game got updated.  When I finally realized that I would never be able to make it truly and easily sharable, I gave up.

But for something like the play-by-turn forum or email-based game you guys are describing, having a virtual table that tracked the game's state while you posted the new URL after each move doesn't seem so crazy...
