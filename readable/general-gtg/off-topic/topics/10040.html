In computer programming, this would be:

Monolithic design vs. object oriented design.

In monolithic, everything is in one big block.  You only have to copy one file over, but searching for anything can be long and tedious.  Maintaining monolithic code is a lot harder.

In object oriented design, you have a separate file for each "object" (usually a section of code representing some aspect of the program that may be accessed from multiple different locations in the main code or that may have multiple instances of itself created, like building blocks).  Finding a bug in an object just means checking through that object's code.  You have a lot more files to keep track of so file names are very important, but maintenance is much easier.

In every case I have seen, the object oriented design was much better overall than the monolithic approach.  In this case, I have to agree with Silverleaf.  It makes it much easier to search for the relevant thread this way.  We may get more threads overall, but getting to the one we want when we want it becomes much easier.
